These routes create accounts, sign people in and manage their sessions. Every route is under `/v1/auth`, and [Authentication](/authentication/) explains the token formats.

## Shared behavior

Most routes here need no `Authorization` header, because the request has its own ticket, code or credential. The routes that need a user session token, except [log out](#log-out), reject a bot token and an OAuth2 bearer token with 403 `ACCESS_DENIED`.

Each sign-in creates one session, and a session lasts until it is revoked. When a session is revoked, its Gateway connection gets [Invalid Session](/gateway/overview/#invalid-session) with `d: false`.

<a id="authentication-token-response"></a>

## Authentication token response object

A new session token and the account it belongs to. Every route that signs someone in returns these fields.

### Structure

| Field | Type | Description |
| --- | --- | --- |
| token | string | The new user session token, returned only here |
| user_id | snowflake | The authenticated user ID |
| user | [partial user](/http-api/users/#partial-user-object) object | The authenticated account |
| entry?<sup>1</sup> | ?[guild entry](/http-api/users/current-user/#guild-entry-object) object | The community to open next, from the invite used at sign-up |

<sup>1</sup> Returned only by registration, and null when no invite applied

When a route can return this object or a different one, check for `token`.

### Structure

| user_id | snowflake | The ID of the account waiting for approval |

## Network block response

A request from a blocked network returns 403 `GLOBAL_IP_BANNED` or `GLOBAL_IP_TEMPORARILY_BANNED`, and the [error response](/http-api/#error-response) has these extra fields.

| Field | Description |
| --- | --- |
| `ip_address` | The client IP address |
| `appeal_email` | Always `null` on a self-hosted instance |
| `appeals_supported` | Always `false` on a self-hosted instance |
| `ban_kind` | `permanent`, or `temporary_24h` for any ban with an expiry |
| `expires_at` | When the ban ends as an ISO 8601 timestamp, or `null` |
| `reason` | The rule behind the block as `title` and `url`, or `null` |
| `product_name` | The instance name used in `message` |

A blocked network can still load `GET /.well-known/osaca`, which the app uses to show the block message. Password, passkey and MFA sign-in still respond from a blocked network, and a suspended or closed account sees its [enforcement notice](#enforcement-notice-object). Every other result is the same network block error.

## Enforcement notice object

`ACCOUNT_SUSPENDED_TEMPORARILY` and `ACCOUNT_SUSPENDED_PERMANENTLY` errors have a `notice` field with the enforcement notice for the account, in the request locale.

| Field | Description |
| --- | --- |
| `decision_id` | The decision reference, or `null` |
| `kind` | `suspension` or `closure` |
| `permanent` | `true` for a suspension with no end date |
| `issued_at` | When the decision was made, or `null` |
| `ends_at` | When the suspension ends, or `null` |
| `deletion_at` | When the account will be deleted, or `null` |
| `summary` | One sentence saying what happened |
| `effects` | What the decision means for the account |
| `rule` | The rule broken as `title` and `url`, or `null` |
| `facts` | The finding, then where and when it happened |
| `statement` | A note from the team, or `null` |
| `how_we_decided` | How the case came to the team and who decided |
| `appeal` | `email` and `deadline`, or `null` |
| `redress` | Other ways to challenge the decision |

Lines in `effects`, `facts` and `redress` can have Markdown links, `[text](url)`, which the app shows as links.

## MFA challenge response object

Sign-in routes return this object when the account has a second factor. Finish with [complete login with TOTP](#complete-login-with-totp) or [complete login with WebAuthn MFA](#complete-login-with-webauthn-mfa).

### Structure

| Field | Type | Description |
| --- | --- | --- |
| mfa | boolean | Always `true` |
| ticket | string | The ticket for the MFA route, valid for 5 minutes or until 5 wrong codes |
| allowed_methods | array[string] | The methods the account can use, from `totp`, `webauthn` and `backup_codes` (max 10 items) |
| totp | boolean | Whether the account has an authenticator app |
| webauthn | boolean | Whether passkeys are turned on as a second factor |
| backup_codes | boolean | Whether the account has an unused backup code |

Backup codes go to [complete login with TOTP](#complete-login-with-totp) as `code`.

## Register an account

<RouteHeader method="POST" path="/v1/auth/register" unauthenticated />

Creates an account and returns an [authentication token response](#authentication-token-response), or a [registration pending approval response](#registration-pending-approval-response-object) when an admin has to approve it. The request needs a [CAPTCHA](/topics/captcha/), and joining a community sends [Guild Member Add](/gateway/events/#guild-member-add).

A body with only `global_name` creates an [instant account](/admin-api/instance/#auth-configuration-object) with a username made from that name. The person keeps it by [claiming it](/http-api/users/current-user/#claim-an-account).

If you lose the response, try to sign in before you retry, because registration isn't idempotent.

### Request headers

| Field | Type | Description |
| --- | --- | --- |
| X-Captcha-Token? | string | The solved ALTCHA challenge, see [CAPTCHA handling](/topics/captcha/) |
| Accept-Language? | string | The language for the account |

### JSON body

| Field | Type | Description |
| --- | --- | --- |
| username?<sup>1</sup> | string | The username (1-32 characters, letters, digits and underscores) |
| global_name? | string | The display name (1-32 characters) |
| password?<sup>2</sup> | string | The password (8-256 characters) |
| consent?<sup>3</sup> | boolean | Whether the person accepted the terms of service (default false) |
| invite_code? | ?string | An invite to accept after registration (0-256 characters) |
| registration_url_code?<sup>4</sup> | ?string | A registration URL code from an admin (1-128 characters) |
| theme? | string | The starting theme, one of `dark`, `dark_legacy`, `coal`, `light` or `system` |
| setup_token?<sup>5</sup> | ?string | The setup token of a new self-hosted instance (1-256 characters) |

<sup>1</sup> Without it, OSACA makes one from `global_name`. A taken name returns the field code `USERNAME_ALREADY_TAKEN`

<sup>2</sup> A known breached password returns the field code `PASSWORD_IS_TOO_COMMON`

<sup>3</sup> Must be true on an instance with terms or a privacy policy, or you get the field code `MUST_AGREE_TO_TOS_AND_PRIVACY_POLICY`

<sup>4</sup> Lets the person sign up while registration is closed. An unknown code returns 400 `REGISTRATION_URL_INVALID`

<sup>5</sup> Needed until the first admin account exists. A missing value returns the field code `SETUP_TOKEN_REQUIRED`, and the account that uses it gets the full [Admin ACL](/admin-api/#acl-registry)

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 200 | [authentication token response](#authentication-token-response) \| [registration pending approval response](#registration-pending-approval-response-object) | The account was created or is waiting for approval |
| 400 | [error response](/http-api/#error-response) | `CAPTCHA_REQUIRED` or `INVALID_CAPTCHA` |
| 400 | [error response](/http-api/#error-response) | `REGISTRATION_CREDENTIALS_REQUIRED` when an account waiting for approval has no password |
| 403 | [error response](/http-api/#error-response) | `REGISTRATION_CLOSED`, `INSTANT_ACCOUNTS_DISABLED` or `CONTENT_BLOCKED` |
| 423 | [error response](/http-api/#error-response) | `GENERAL_ERROR` when another request is creating the first admin account of a new instance |

The rate limit is 10 requests per 10 seconds, on the `auth:register` bucket.

## Log in with a password

<RouteHeader method="POST" path="/v1/auth/login" unauthenticated />

Signs in with a username and a password. Returns an [authentication token response](#authentication-token-response), or an [MFA challenge response](#mfa-challenge-response) when the account has a second factor. The request needs a [CAPTCHA](/topics/captcha/).

An unknown account and a wrong password both return the field code `INVALID_LOGIN_OR_PASSWORD`.

Signing in turns a disabled account back on and cancels a deletion the person scheduled.

### Request headers

| Field | Type | Description |
| --- | --- | --- |
| X-Captcha-Token? | string | The solved ALTCHA challenge, see [CAPTCHA handling](/topics/captcha/) |
| X-OSACA-Client-Properties? | string | Base64 JSON with the app's `os`, for the [client info](#client-info-object) |
| User-Agent? | string | The client string shown in [list authentication sessions](#list-authentication-sessions) |

### JSON body

| Field | Type | Description |
| --- | --- | --- |
| login<sup>1</sup> | string | The username (1-320 characters) |
| password | string | The password (8-256 characters) |
| invite_code? | ?string | An invite to accept after a sign-in with no second factor (0-256 characters) |

<sup>1</sup> `alex`, `alex#0` and `alex@` followed by the instance host all mean the same account

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 200 | [authentication token response](#authentication-token-response) \| [MFA challenge response](#mfa-challenge-response) | The credentials were accepted |
| 403 | [error response](/http-api/#error-response) | A suspension code with an [enforcement notice](#enforcement-notice-object), after the last factor |

The rate limit is 10 requests per 10 seconds, on the `auth:login` bucket.

## Log out

<RouteHeader method="POST" path="/v1/auth/logout" bot />

Revokes the session whose token is in the `Authorization` header and returns 204. Other sessions stay signed in. A bot token is accepted and revokes nothing. When the instance [cleans up unclaimed accounts](/admin-api/instance/#unclaimed-account-cleanup-object) on the last sign-out, ending the last session of an account nobody can sign in to again schedules its deletion 24 hours later.

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 204 | empty | The session was revoked |

The rate limit is 20 requests per 10 seconds, on the `auth:logout` bucket.

## Recover an account

<RouteHeader method="POST" path="/v1/auth/recover" unauthenticated />

Sets a new password with the recovery key from a recovery kit and returns an [account recovery response](#account-recovery-response-object) with a new key. The request needs a [CAPTCHA](/topics/captcha/).

:::caution[Recovery signs out every session and replaces the key]
The old key stops working and every session is signed out. For an account with a second factor, nothing changes until the MFA route accepts the ticket.
:::

### Request headers

| Field | Type | Description |
| --- | --- | --- |
| X-Captcha-Token? | string | The solved ALTCHA challenge, see [CAPTCHA handling](/topics/captcha/) |

### JSON body

| Field | Type | Description |
| --- | --- | --- |
| login | string | The username (1-320 characters) |
| recovery_key<sup>1</sup> | string | The recovery key from the recovery kit (1-128 characters) |
| password | string | The new password (8-256 characters) |

<sup>1</sup> Spaces, dashes and letter case are ignored

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 200 | [account recovery response](#account-recovery-response-object) | The password and the recovery kit were replaced |
| 400 | [error response](/http-api/#error-response) | The field code `INVALID_RECOVERY_KEY`, also for an unknown username, or `PASSWORD_IS_TOO_COMMON` |

The rate limit is 10 requests per minute, on the `auth:recover` bucket.

## Terminate authentication sessions

<RouteHeader method="POST" path="/v1/auth/sessions/logout" mfa />

Signs out the sessions you name and returns 204. It needs [sudo mode](/http-api/users/mfa/#sudo-mode), from the `X-OSACA-Sudo-Mode-JWT` header or a password or MFA proof in the body. Leave out the `id_hash` of the current session to stay signed in.

### JSON body

| Field | Type | Description |
| --- | --- | --- |
| session_id_hashes | array[string] | The `id_hash` values of the sessions to sign out (max 100 entries) |
| password? | string | The password, for an account with no authenticator app and no passkey (8-256 characters) |

| webauthn_response? | [WebAuthn assertion](#webauthn-assertion) object | The passkey result, for `webauthn` |

| Status | Body | Condition |
| --- | --- | --- |
| 204 | empty | The sessions were signed out |
| 403 | [error response](/http-api/#error-response) | `SUDO_MODE_REQUIRED` when proof is missing |

The rate limit is 20 requests per 10 seconds, on the `auth:sessions:logout` bucket.

## Complete desktop handoff

<RouteHeader method="POST" path="/v1/auth/handoff/complete" />

Approves a handoff and creates a session for the other device. Send the approving device's session token in the `Authorization` header or as `token`. Returns a [handoff completion](#handoff-completion-object) object for the `deep_link` return method, or 204 for `code`.

### JSON body

| Field | Type | Description |
| --- | --- | --- |
| code | string | The handoff code |
| token? | string | The approving device's session token, when you don't send `Authorization` |
| user_id | snowflake | The ID of the approving account |
| return_method? | string | `deep_link` or `code` (default `code`) |

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 200 | [handoff completion](#handoff-completion-object) object | The handoff was approved with `deep_link` |
| 204 | empty | The handoff was approved with `code` |
| 400 | [error response](/http-api/#error-response) | `INVALID_HANDOFF_CODE` or `HANDOFF_CODE_EXPIRED` when the code is unknown or expired |
| 400 | [error response](/http-api/#error-response) | `HANDOFF_CODE_ALREADY_USED` when the same network already approved this code |
| 401 | [error response](/http-api/#error-response) | `INVALID_TOKEN` when the approving session is not active |
| 429 | [error response](/http-api/#error-response) | `HANDOFF_ATTEMPTS_EXCEEDED` when this IP address has 5 failed handoff attempts in 15 minutes, with `retry_after` |

The rate limit is 10 requests per minute, on the `auth:handoff:complete` bucket.

## Create origin handoff

Stores encrypted app state for 2 minutes so another web origin of the same instance can take it once. Returns an [origin handoff](#origin-handoff-object) object. The sender keeps the encryption key, and OSACA only stores the payload.

### JSON body

| Field | Type | Description |
| --- | --- | --- |

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 200 | [origin handoff](#origin-handoff-object) object | The state was stored |

The rate limit is 3 requests per 10 minutes, on the `auth:origin_handoff:create` bucket.
