An account can use a TOTP authenticator app and WebAuthn credentials such as passkeys as a second factor, with one-use backup codes as a fallback. A registered passkey works for [sudo mode](#sudo-mode) and passwordless login right away, but password login only asks for it after [Set WebAuthn two-factor authentication](#set-webauthn-two-factor-authentication) turns it on.

## TOTP parameters

OSACA accepts six-digit HMAC-SHA-1 codes with a 30-second time step and one step of clock skew either way. Your client generates the Base32 secret, shows it to the user and sends it with a code to [Enable TOTP MFA](#enable-totp-mfa).

## Backup codes

An account gets 10 backup codes when it enables TOTP, and when it turns on passkeys as a second factor while it has no unused codes. Each code works once, and OSACA ignores case, spaces and hyphens when it compares them. You can send a backup code wherever a TOTP code is accepted, except in [Enable TOTP MFA](#enable-totp-mfa). OSACA deletes every code when the account is left with no second factor.

## Sudo mode

Sudo mode is a recent proof that the account holder is present, and security-sensitive operations need it. Send the proof as [sudo verification object](#sudo-verification-object) fields in the JSON body, or send an earlier token in the `X-OSACA-Sudo-Mode-JWT` header. After a TOTP, backup code or passkey proof, OSACA returns a token in the same response header, and it works for five minutes on any of the account's sessions. A password proof returns no token, and the account sends `password` on each call.

The first row that matches the account says which proofs it can send.

| Account state | Proof to send |
| --- | --- |
| A second factor is turned on | `mfa_method` of `totp` or `webauthn` with its fields |
| Has a password | `password`, or `webauthn` with a passkey |
| None of these | Nothing, and the operation goes ahead |

Without a proof, the request returns 403 `SUDO_MODE_REQUIRED` with the [sudo mode methods](#sudo-mode-methods-object) fields. A wrong password returns 400 `INVALID_PASSWORD` on the path `password`, and a wrong TOTP code, backup code or passkey assertion returns 400 `INVALID_MFA_CODE` on the path `mfa_code`. The `totp` method allows 10 attempts per 15 minutes for each account, and a correct code resets the count.

## Sudo mode methods object

`SUDO_MODE_REQUIRED` responses have these fields at the top level of the [error response](/http-api/#error-response).

### Structure

| Field | Type | Description |
| --- | --- | --- |
| has_mfa | boolean | Whether the account has TOTP or at least one passkey |
| methods | [sudo mode method availability](#sudo-mode-method-availability-object) object | The proofs the account can give |

## Sudo mode method availability object

### Structure

| Field | Type | Description |
| --- | --- | --- |
| totp | boolean | Whether the account has TOTP enabled |
| webauthn | boolean | Whether the account has at least one passkey |
| backup_codes<sup>1</sup> | boolean | Whether the account has at least one unused backup code |
| password? | boolean | Whether the account can prove sudo mode with its password |

<sup>1</sup> A backup code goes in `mfa_code` with `mfa_method` set to `totp`, also on an account without TOTP. There is no `backup_codes` method

## Enable TOTP MFA

<RouteHeader method="POST" path="/v1/users/@me/mfa/totp/enable" mfa />

Enables TOTP and returns 10 new backup codes. You need [sudo mode](#sudo-mode) and a [verified account](/http-api/users/#account-tiers). Sends a [User Update](/gateway/events/#user-update) Gateway event.

### JSON body

The body extends the [sudo verification object](#sudo-verification-object) with these fields.

| Field | Type | Description |
| --- | --- | --- |
| secret | string | Base32 TOTP secret your client generated (1-256 characters) |
| code | string | Current TOTP code for `secret`, not a backup code (1-32 characters) |

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 200 | [MFA backup codes](#mfa-backup-codes-object) object | TOTP was enabled |
| 400 | [error response](/http-api/#error-response) | `INVALID_CODE` on the path `code`, or `TWO_FA_ALREADY_ENABLED` when TOTP is already enabled |
| 403 | [error response](/http-api/#error-response) | `ACCOUNT_VERIFICATION_REQUIRED` when the account isn't verified |

The rate limit is 10 requests per minute, on the `user:mfa:totp:enable` bucket.

## Disable TOTP MFA

<RouteHeader method="POST" path="/v1/users/@me/mfa/totp/disable" mfa />

Disables TOTP under [sudo mode](#sudo-mode) and returns 204. This deletes every backup code unless passkeys stay on as a second factor. Sends a [User Update](/gateway/events/#user-update) Gateway event.

### JSON body

The body extends the [sudo verification object](#sudo-verification-object) with this field.

| Field | Type | Description |
| --- | --- | --- |
| code<sup>1</sup> | string | Current TOTP code or unused backup code (1-32 characters) |

<sup>1</sup> Without a sudo token or `mfa_method`, `code` also proves sudo mode

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 204 | empty | TOTP was disabled |
| 400 | [error response](/http-api/#error-response) | `INVALID_CODE` on the path `code`, or `INVALID_MFA_CODE` on the path `mfa_code` when `code` proves sudo mode |
| 400 | [error response](/http-api/#error-response) | `TWO_FACTOR_REQUIRED` when TOTP isn't enabled |

The rate limit is 10 requests per minute, on the `user:mfa:totp:disable` bucket.

## Register WebAuthn credential

<RouteHeader method="POST" path="/v1/users/@me/mfa/webauthn/credentials" />

Adds a WebAuthn credential to the account and returns 204. A challenge works only once, even when registration fails, and you need new options to try again. Sends a [WebAuthn Credentials Update](/gateway/events/#webauthn-credentials-update) Gateway event, and a [User Update](/gateway/events/#user-update) event for the account's first credential.

### JSON body

| Field | Type | Description |
| --- | --- | --- |
| response | [WebAuthn registration response](#webauthn-registration-response-object) object | The authenticator's response to the challenge |
| challenge | string | Challenge from [Create WebAuthn registration options](#create-webauthn-registration-options) (1-1024 characters) |
| name | string | Name for the credential (1-100 characters) |

### Response

| Status | Body | Condition |
| --- | --- | --- |
| 204 | empty | The credential was registered |
| 400 | [error response](/http-api/#error-response) | `INVALID_WEBAUTHN_CREDENTIAL`, `INVALID_WEBAUTHN_PUBLIC_KEY_FORMAT` or `INVALID_WEBAUTHN_CREDENTIAL_COUNTER` |
| 400 | [error response](/http-api/#error-response) | `WEBAUTHN_CREDENTIAL_LIMIT_REACHED` when the account has 10 credentials |
| 403 | [error response](/http-api/#error-response) | `ACCOUNT_VERIFICATION_REQUIRED` when the account has no password or passkey yet |

The rate limit is 10 requests per minute, on the `mfa:webauthn:register` bucket.

## Set WebAuthn two-factor authentication

<RouteHeader method="PUT" path="/v1/users/@me/mfa/webauthn/two-factor" mfa />

Sends a [User Update](/gateway/events/#user-update) Gateway event when the setting changes.

### JSON body

| Field | Type | Description |
| --- | --- | --- |
| enabled | boolean | Whether passkeys are a second factor at password login |

### Response

| 403 | [error response](/http-api/#error-response) | `ACCOUNT_VERIFICATION_REQUIRED` when turning it on and the account isn't verified |

The rate limit is 10 requests per minute, on the `mfa:webauthn:two_factor` bucket.
